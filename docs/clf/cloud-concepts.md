# 雲端概念：為什麼大家都往雲端搬？

> 這是 CLF 的第一個領域（Domain 1，佔 24%）。這一關不要你會動手架設系統，而是要你**懂雲端的好處與價值**。觀念題超多，讀通這篇就贏一半。

<Analogy title="☕ 比喻：自己開咖啡店 vs. 進駐美食街">

- **自建機房** = 自己租店面開咖啡店：裝潢、水電、桌椅全要先砸一大筆錢，生意好壞都得付房租。
- **用雲端** = 進駐美食街的攤位：水電桌椅都現成，**用多少付多少**，人潮暴增隨時擴攤，收掉也不心疼。

</Analogy>

## 雲端的六大優勢（考試最愛考）

這是 AWS 官方整理的「<Term en="Six Advantages of Cloud Computing" desc="AWS 官方歸納採用雲端的六大好處，CLF 幾乎必考。">雲端運算六大優勢</Term>」，請把它當成口訣記起來。

| 優勢 | 白話解釋 |
| --- | --- |
| **把前期資本支出換成變動支出** | 不用一次砸大錢買伺服器（<Term en="Capital Expenditure" desc="資本支出：一次性購置硬體、機房的大筆前期投資。">CapEx</Term>），改成用多少付多少的日常花費（<Term en="Operating Expenditure" desc="營運支出：隨用量產生的經常性費用，像水電帳單。">OpEx</Term>）。 |
| **享受規模經濟帶來的優惠** | AWS 服務全球上百萬客戶，採購量超大，成本被攤平，所以你用的單價比自己買便宜。 |
| **不用再猜容量** | 以前要先猜「會有多少人用」來買機器，猜太多浪費、猜太少當機。雲端要多少開多少，隨時調整。 |
| **提升速度與敏捷** | 需要一台新伺服器？幾分鐘內就開好，不用等採購、進貨、安裝好幾週，想法能更快落地。 |
| **省下維運機房的錢** | 不用再花錢租機房、養冷氣、請人 24 小時顧機器，把錢和心力放在真正賺錢的業務上。 |
| **幾分鐘內布及全球** | 滑鼠點幾下，就能把服務部署到世界各地的機房，讓各國使用者都連得又快又順。 |

:::note[一句話記重點]
雲端把「**先大筆投資、還要自己養機房**」變成「**隨開隨用、看帳單付費**」。這六點只要能認得、分得出來，CLF 的觀念題就穩了。
:::

## 三種雲端部署模型

部署模型講的是「你的系統到底放在哪裡」。CLF 要你分得出三種的差別與適用情境。

| 模型 | 是什麼 | 什麼時候用 |
| --- | --- | --- |
| **雲端（Cloud）** | 整套系統都蓋在雲上，不碰自家機房 | 新創、新專案，想完全享受雲端彈性與免維運 |
| **混合（Hybrid）** | 一部分放雲端、一部分留在自家機房，兩邊打通 | 有法規或舊系統綁在地端，但想逐步把其他部分搬上雲 |
| **地端（On-Premises）** | 全部自己買硬體、放自家機房（也叫私有雲） | 法遵或資安要求極嚴、資料不能出門的情況 |

<Scenario title="情境：一家傳統銀行要上雲">

銀行的核心帳務系統受法規限制，資料得留在自家機房；但新推出的手機 App、行銷活動網站想享受雲端的彈性擴展。這時最合理的選擇就是**混合（Hybrid）**：核心留地端、對外服務上雲，兩邊安全連線。

</Scenario>

## 雲端經濟與 TCO

<Term en="Pay-as-you-go" desc="隨用隨付：用多少算多少，不綁約、不用預先買斷。">隨用隨付</Term>是雲端省錢的核心精神，但考試更愛問一個更完整的概念：**總持有成本**。

<Term en="Total Cost of Ownership" desc="總持有成本：把一項資產從購置到維運、淘汰的所有花費全部加總，而不只看購買價。">TCO（總持有成本）</Term>的意思是：算一套系統要花多少錢，**不能只看買機器的錢**，還要把機房租金、電費、冷氣、網路、維運人力、硬體汰換通通加進去。

<Analogy title="🚗 比喻：養一台車的真實成本">

買車不是付完車價就沒事了——還有油錢、保養、保險、停車位、折舊。這些全加起來才是「養這台車」的真實成本，也就是 TCO 的概念。自建機房的「隱藏費用」往往比想像中高很多。

</Analogy>

:::info[為什麼雲端通常比較省？]
自建要**先付一大筆、還得養著整個機房**，而且常常買太多、用不滿。雲端用多少付多少、不用養機房、硬體汰換是 AWS 的事，把這些隱藏成本都算進 TCO 後，長期算下來通常更划算。
:::

## Well-Architected 六大支柱

AWS 用「<Term en="Well-Architected Framework" desc="AWS 架構完善的框架：評估雲端系統好壞的六個面向。">架構完善的框架</Term>」來衡量一套雲端系統蓋得好不好，共有**六大支柱**。CLF 層級不用深究細節，只要**知道有這六根、認得名字**即可。

| 支柱 | 白話 |
| --- | --- |
| **卓越營運** | 系統能順利運作、持續改善 |
| **安全性** | 保護資料、系統與資產 |
| **可靠性** | 出事能恢復、該在的時候都在 |
| **效能效率** | 用對資源、跑得又快又有效率 |
| **成本最佳化** | 花在刀口上，不浪費錢 |
| **永續性** | 減少環境衝擊、節能減碳 |

:::tip[💡 CLF 常見考點提示]
CLF 這個領域最愛考**概念題**，最常見的是：
- **雲端的好處**（六大優勢，尤其「不用猜容量」「幾分鐘布及全球」）
- **CapEx vs OpEx**（把前期資本支出換成變動支出）
- **彈性與敏捷**（想開就開、用多少付多少）

看到題目在問「採用雲端的好處」「為什麼比自建省」，答案幾乎都往這幾個方向走。
:::
