# 帳單警示與免費方案避坑：別讓帳單嚇到你

> 新手剛開 AWS 帳號，最大的恐懼就是：「**我會不會不小心被扣一大筆錢？**」這篇帶你搞懂免費方案（Free Tier）怎麼用、常見爆帳單的坑長什麼樣，最後動手設好**兩道防線**——預算告警＋帳單告警，讓你安心練習，不怕半夜被帳單叫醒。

<Vocab title="📌 先認識這篇會出現的名詞（完全沒碰過也能懂）">

- **免費方案（Free Tier）**：AWS 給新手的「**試用額度**」——在一定範圍內用某些服務不用錢，是你練習的最佳沙盒。
- **帳單告警（Billing Alert）**：當你的花費或用量快超標時，系統「**主動寄信通知你**」的警報，避免默默被扣錢。
- **預算（Budget）**：你先訂一個「**這個月最多花多少**」的門檻，超過或快超過就通知你。
- **執行個體（Instance）**：你租來的一台虛擬機器（例如一台 EC2）。開著就算用，沒關就一直計費。
- **用多少付多少（Pay-as-you-go）**：AWS 的計費精神，像水電費——用越多付越多，沒用就不收。好處是省錢，壞處是**忘了關就一直跳表**。

</Vocab>

## 為什麼要先搞懂「錢」這件事？

<Analogy title="🍽️ 比喻：AWS 像吃到飽，但有「加價品項」">

AWS 很多服務在免費方案內，就像吃到飽餐廳的「**基本菜色**」——隨便拿都不用加錢。但有些品項（像和牛、生蠔、特調酒）是**要另外加價**的，菜單上有寫，只是你沒細看。

新手爆帳單，幾乎都不是因為「吃太多」，而是**沒看清楚哪些要加價**：隨手點了個不在免費額度的服務、或是離開餐廳時忘了結帳（忘了關機器），結果月底帳單一來就嚇一跳。

先搞懂規則、先裝好警報，你就能安心地「吃」，知道什麼免費、什麼要錢、快超標時有人提醒你。

</Analogy>

AWS 是「**用多少付多少（Pay-as-you-go）**」，這很省錢，但也代表**沒有人會主動幫你喊停**——除非你自己設好警報。所以在開始玩任何服務之前，先花十分鐘把這篇的兩道防線設好，是最划算的投資。

## 免費方案（Free Tier）有三種，別搞混

很多新手以為「免費方案」就是「永遠免費」，結果一過期就開始被扣錢還不知道。其實 AWS 的免費方案分成**三種類型**，搞懂差別才不會踩雷：

| 類型 | 白話解釋 | 期限 | 常見例子 |
| --- | --- | --- | --- |
| **12 個月免費** | 新帳號開通起算 12 個月內，每月給你一定額度 | 從註冊起 12 個月 | EC2 `t2.micro`／`t3.micro` 每月 750 小時、S3 標準儲存 5 GB、RDS 每月 750 小時 |
| **永久免費（Always Free）** | 不限時間，每月都有的免費額度，過幾年也還在 | 永久（每月重置） | Lambda 每月 100 萬次請求、DynamoDB 25 GB 儲存、CloudWatch 10 個自訂指標 |
| **短期試用（Trials）** | 從你第一次啟用某服務起算，短期內免費試玩 | 通常 30～90 天不等 | 部分服務（如 Amazon SageMaker、Inspector）的限時試用方案 |

:::tip[💡 新手記法]
- **12 個月免費**：像「開卡禮」，期限到了就恢復收費，**最容易因為過期沒注意而被扣錢**。
- **永久免費**：像「每月固定的免費午餐」，額度用完當月才收費，下個月又重置。
- **短期試用**：像「限時體驗券」，從你按下試用那刻開始倒數。
:::

:::warning[⚠️ 額度數字會變，實際以官方為準]
上表的時數、GB 數、次數都是撰文當下的常見額度，AWS 可能隨時調整。**使用前請務必以 [AWS 免費方案官方頁面](https://aws.amazon.com/free/) 公布的最新內容為準**，別把這裡的數字當成保證。另外，EC2 的 750 小時／月是「**一台**機器整月開著」的量；你同時開兩台，額度就會**兩倍速**用完。
:::

## 新手最常見的「爆帳單」原因

知道坑在哪，才躲得掉。以下是新手最容易中的幾種：

- **忘了關 EC2 執行個體**：開了一台機器練習，練完直接關瀏覽器就走了——但機器還開著，**24 小時持續計費**。
- **用到不在免費額度的服務或規格**：免費的是 `t2.micro`／`t3.micro`，你手滑選了更大的 `t3.large`，或開了根本不在免費方案的服務，分分鐘都在收費。
- **流量（資料傳輸）超量**：資料「**傳出去**」AWS 到網際網路是要錢的，免費額度有限，大量下載或影片外流很容易超標。
- **開了測試資源沒刪**：建立了資料庫、彈性 IP、EBS 磁碟、NAT 閘道這類「**開著就算錢**」的資源，練習完忘了刪，它們會默默地月復一月計費。

<Scenario title="真實情境：小美的第一張 AWS 帳單">

剛學 AWS 的小美，週末跟著教學開了一台 EC2 練習部署網站。做到一半有事出門，直接闔上筆電就走了。她以為「關掉瀏覽器＝關掉機器」，但其實那台 `t3.medium`（不是免費的 `micro`）還在雲端 24 小時運轉。

她還順手開了一個 NAT 閘道測試連線，也忘了刪。兩週後月底帳單寄來——**47 美元**。小美嚇壞了，心想「我不是用免費方案嗎？」

問題出在：**規格選錯（不在免費額度）＋忘了關機＋測試資源沒刪**，三個坑一次踩滿。如果她一開始就設好帳單告警，花費剛破 1 美元那天就會收到警報，根本不會拖到月底。

</Scenario>

## 🛠️ 動手做：幫自己設好兩道防線

這是本篇的重點。花十分鐘設好這兩道防線，之後就能安心練習。

:::info[先做這一步：允許 IAM 使用者看帳單]
如果你是用管理者（Root）帳號直接操作，可以略過。若你用的是 IAM 使用者，記得先用 Root 登入，到帳戶設定裡勾選「**IAM user and role access to Billing information（允許 IAM 存取帳單資訊）**」，否則下面的預算、帳單頁面會打不開。
:::

### 第一道防線：用 AWS Budgets 設每月成本預算 + 告警

<Term en="AWS Budgets" desc="設定成本或用量的預算門檻，達到或預測將超過時自動寄信告警的服務。">AWS Budgets（預算）</Term> 讓你先設一個「這個月最多花多少」的門檻，一旦接近或超過就寄信通知你。對新手來說，門檻設得**很低**（例如 1 美元）就對了——因為你正常練習幾乎不該花到錢，一旦超過，代表「有東西不對勁」。

1. 登入 AWS 主控台，右上角帳號名稱 → 進入 **Billing and Cost Management（帳單與成本管理）**。
2. 左側選單點 **Budgets（預算）** → 按 **Create budget（建立預算）**。
3. 範本選 **Zero spend budget（零花費預算）** 最簡單；想自訂就選 **Cost budget（成本預算）**，期間選 **Monthly（每月）**。
4. 設定預算金額，新手建議填 `1`（美元）——意思是「**只要這個月花超過 1 美元就提醒我**」。
5. 新增**告警門檻**：設實際花費達 `85%` 告警一次、達 `100%` 再告警一次；建議也勾「**Forecasted（預測將超過）**」提前示警。
6. 填你的收件 Email，儲存。之後只要花費逼近門檻，信箱就會收到警報。

```bash
# （進階，選用）用 CLI 查看目前帳號底下已建立的預算清單
$ aws budgets describe-budgets \
    --account-id 你的12位數帳號ID
```

### 第二道防線：開啟 Free Tier 用量告警 / 帳單告警

預算是盯「**金額**」，Free Tier 用量告警則是盯「**免費額度用到幾成**」——在你快把免費額度用完、即將開始收費之前就先提醒你。這兩個一起開，等於金額和用量都有人幫你看。

1. 一樣在 **Billing and Cost Management** 頁面，左側點 **Billing preferences（帳單偏好設定）**。
2. 勾選 **Receive AWS Free Tier alerts（接收免費方案用量告警）**，填入收件 Email——當某項免費額度用到約 85% 時就會寄信。
3. 勾選 **Receive CloudWatch billing alerts / 啟用帳單告警**，開啟後 AWS 才會開始把「預估費用」送到 CloudWatch，你才能設帳單告警。
4. （加分）到 <Term en="Amazon CloudWatch" desc="AWS 的監控服務，可針對各種指標設定告警。">CloudWatch</Term> → **Alarms（告警）**，用 `EstimatedCharges`（預估費用）這個指標設一個「超過 X 美元就通知」的告警，當作第三層保險。

:::tip[💡 為什麼兩道都要？]
**Budgets 盯金額、Free Tier 告警盯用量**，角度不同、互補。例如你可能金額還沒破 1 美元，但 S3 的 5 GB 免費額度已經快滿——這時 Free Tier 告警會先叫你，讓你在真正被收費前就處理。
:::

### 順手認識：用 Cost Explorer 看錢花在哪

設好警報後，萬一真的收到告警，你會想知道「**到底是哪個服務在花錢**」。這時就打開 <Term en="AWS Cost Explorer" desc="視覺化分析 AWS 花費與用量趨勢的工具，可依服務、區域等維度拆解。">Cost Explorer（成本探索器）</Term>：它把你的花費畫成趨勢圖，可以按**服務、區域**等維度拆開看，一眼就能抓出「哦，原來是那台忘了關的 EC2」。主控台看圖的介面是免費的，放心用。

<Cost>

**好消息：這兩道防線本身幾乎不花錢。** 每個帳號有**兩個免費的成本／用量預算**（新手設一個零花費預算綽綽有餘）；Free Tier 用量告警、帳單告警、Cost Explorer 的主控台看圖介面都**免費**。真正要注意的反而是你拿來練習的那些資源——練完記得清掉。費用細節請以 [AWS 官方計費說明](https://aws.amazon.com/aws-cost-management/) 為準。

</Cost>

## 🏆 黃金守則：練完就刪、善用額度

兩道防線是「被動警報」，但最好的省錢是「**主動不留爛攤子**」。記住這兩條：

1. **練習完一定要刪掉／關掉不用的資源**：終止（Terminate）測試用的 EC2、刪掉測試資料庫、釋放沒在用的彈性 IP、刪掉 EBS 磁碟與快照。「**關機（Stop）**」有些資源還是會收儲存費，能刪就刪最乾淨。
2. **善用免費額度、選對規格**：練習一律挑免費方案內的規格（如 `t2.micro`／`t3.micro`），別手滑開大機器；優先用永久免費的服務（如 Lambda）來玩，成本幾乎是零。

:::warning[🚑 新手最容易忘的收尾動作]
- **Stop 不等於不收錢**：EC2 關機（Stop）後，掛在上面的 EBS 磁碟仍在計費；確定不用就 **Terminate（終止）** 並刪除磁碟。
- **彈性 IP 閒置也收錢**：配置了卻沒綁在執行中的機器上，反而會被收費，記得釋放。
- **檢查所有區域（Region）**：資源是分區域的，你可能在東京開了機器卻在維吉尼亞找，記得切換區域逐一檢查有沒有遺漏的資源。
:::

## 跟考試的關聯

這篇教你動手設的 **Budgets（預算告警）** 和 **Cost Explorer（花費視覺化）**，正是 SAA 考試 Domain 4「成本最佳化」領域的核心工具。考題常會給你一個情境（例如「希望超過某金額就自動通知」「想視覺化分析哪個服務最花錢」），要你選對工具。你現在親手設過一遍，考試看到這些名詞就不會只是死背——你是真的用過。等進到 SAA 課程，還會再碰到 Cost Anomaly Detection（成本異常偵測）、Cost Allocation Tags（成本分攤標籤）等更進階的治理工具。
