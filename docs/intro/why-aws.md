# 為什麼需要用 AWS？

在學任何 AWS 服務之前，先搞懂一件事：**我們到底為什麼需要它？** 用生活的例子來看最清楚。

<Analogy title="💡 比喻：自己蓋發電廠 vs. 接台電">

想像你要開一家飲料店。

**沒有雲端的年代**，等於你得自己蓋一座發電廠才能開店——先花大錢買伺服器主機、租機房、裝冷氣散熱、請工程師 24 小時顧著，機器壞了半夜還要爬起來修。

**有了 AWS**，就像直接接台電和自來水：**打開開關就有電，用多少付多少**，完全不用管電廠怎麼運作。

</Analogy>

## 實務上，AWS 幫你解決這些真實痛點

<Scenario title="情境一：創業做 App，但不想先燒一大筆錢">

傳統做法要先砸幾十萬買伺服器，萬一 App 沒人用就血本無歸。用 AWS，**刷卡就能開機，一個月可能只花幾百塊**；失敗了直接關掉，不心疼。這就是「**用多少付多少（Pay-as-you-go）**」。

</Scenario>

<Scenario title="情境二：突然爆紅，流量暴增（像雙 11、上新聞）">

自己的機房塞爆就當機，客人全跑光。AWS 可以**幾分鐘內自動長出更多伺服器**撐住流量，熱潮過了再自動縮回去省錢。這就是「**彈性擴展（Scalability）**」——也是 SAA 考試的核心精神。

</Scenario>

<Scenario title="情境三：想讓全世界的使用者都用得順">

你在台灣，但有美國、日本的客人。AWS 在**全球都有機房**，滑鼠點幾下就能把服務部署到當地，讓各地使用者都連得快。自己做？光租海外機房就先累死。

</Scenario>

:::note[一句話總結]
AWS 把「**養一整個 IT 機房的麻煩**」變成「**像用水電一樣：打開水龍頭就有、看帳單付費**」。你只要專心做你的生意／產品，硬體壞掉、機房失火都是 AWS 的事。
:::

## 那「相對其他選擇」，AWS 好在哪？取捨又是什麼？

「上雲」不只有 AWS，還有 Azure、Google Cloud，甚至「乾脆自己買機器自建」也是一條路。簡單對照一下：

- **相對自建機房**：不用先砸大錢買硬體、養機房與維運人力，**開機就能用、用多少付多少**；但長期穩定、流量可預期的超大規模工作負載，自建的「單位成本」反而可能更低——這是取捨。
- **相對 Azure / Google Cloud**：三家核心概念都差不多（運算、儲存、網路、彈性擴展）。AWS 的優勢是**服務數量最多、市占與社群資源最大、教學與範例最好找**；缺點是**選項多到容易眼花**，初學者反而會迷路。
- **共同的取捨**：上雲省了硬體與維運的煩惱，但換來**要看得懂帳單、要會控成本**，用錯服務或忘了關，帳單會嚇到你。

對考照而言，先學 AWS 是最務實的起點：觀念（彈性、可用性、成本最佳化）在各家其實是共通的，之後要轉別家也不難。

## 這跟考試有什麼關係？

SAA 考的是「**解決方案架構師**」。這個角色的工作，就是幫公司決定**怎麼聰明地組合這些 AWS 服務**，做到又穩、又快、又省錢。

先懂「為什麼用」，後面每個服務你才知道它在解決什麼問題，而不是死背。

:::warning[🚑 常見誤解]
剛接觸雲端最容易有這三個誤會，先破除再往下學：

- **「上雲一定最便宜」**：雲端是省了「先砸大錢」與維運人力，**不等於**總帳一定最省。用錯服務、忘記關、或流量很穩定卻硬要用高彈性方案，帳單反而更貴。便宜的前提是**會控成本**。
- **「學 AWS 就被綁死一家」**：核心觀念（彈性擴展、高可用、成本最佳化）各家共通，學會後轉 Azure／Google Cloud 門檻不高。被綁死的通常不是「觀念」，而是你**過度依賴某些專屬服務**又沒做好抽象——那是架構選擇，不是學 AWS 的錯。
- **「考到證照就等於會實作」**：證照證明你**懂觀念、會選型**，但真正上手還是要**自己動手開過、踩過坑**。所以本站每篇都附實作；證照是地圖，動手才是真的走過。
:::
