# 你的第一個動手實作：EC2 + S3

> 恭喜你走到「動手做」這一步！前面幾篇我們一直在講「為什麼」和「是什麼」，這篇終於要**親手開一台伺服器、建一個雲端倉庫**，把 AWS 兩大主角玩過一次。全程走**免費額度（Free Tier）**，照著做不會扣到錢（只要你最後乖乖清理）。

<Vocab title="📌 先認識這篇會出現的名詞（完全沒碰過也能懂）">

- **EC2（Elastic Compute Cloud）**：AWS 上「**租來的一台電腦／伺服器**」，是這篇的「運算」主角。
- **執行個體（Instance）**：你實際開出來的那**一台** EC2 虛擬機，像你租到手的那台電腦。
- **S3（Simple Storage Service）**：AWS 的「**雲端硬碟／檔案倉庫**」，是這篇的「儲存」主角。
- **貯體（Bucket）**：S3 裡存放檔案的「大容器」，名稱**全球唯一**。
- **區域（Region）**：AWS 在世界各地的機房位置（例如東京、新加坡），你的資源會開在你選的那個區域。

</Vocab>

:::note[💬 閱讀小提示]
看到帶<Term desc="像這樣！滑鼠移到有虛線的名詞上（手機點一下），就會跳出白話解釋。">虛線底線的名詞</Term>，把滑鼠移上去就會跳出白話解釋。所有名詞也整理在 [名詞與服務對照表](/glossary)。
:::

## 為什麼要親手做這一次？

光看文章你永遠記不住「開一台 EC2」到底是什麼感覺。這篇讓你**真的點下按鈕、看到 Linux 的提示字元、把檔案丟上 S3 再抓回來**。做過一次，後面講到任何服務你腦中都有畫面，考試看到情境題也更有感。

<Analogy title="🚗 生活比喻：這就像第一次把車開出停車場">

你可以把駕訓班課本背得滾瓜爛熟，但**真正會開車**，是從你第一次踩油門、車子動起來那一刻開始。這篇就是你的第一次上路：先開一台「電腦」（EC2），再租一個「倉庫」（S3），最後把兩者串起來。

</Analogy>

:::info[開始前的前提]
這篇假設你已經完成前面幾篇的準備：

- 已經**開好 AWS 帳號**，而且平常**不用 Root 使用者**辦公。
- 已經**設好帳單告警（Billing Alarm）**，花超過門檻會收到通知。
- 知道怎麼在主控台右上角**切換區域（Region）**——建議整篇都固定在同一個區域（例如「亞太區域（東京）ap-northeast-1」），比較不會找不到自己開的東西。

還沒做完？先回頭補完再來，這些是你的「安全網」。
:::

## 實作一：啟動一台 EC2 執行個體

目標：開出一台跑 Linux 的伺服器，並成功連進去看到提示字元。

1. 登入 AWS 主控台 → 確認右上角的**區域**是你要用的那個 → 搜尋列輸入 `EC2` → 進入 EC2 服務。
2. 點**啟動執行個體（Launch instance）**。
3. **名稱**：隨便取，例如 `my-first-server`。
4. **應用程式與 OS 映像（AMI）**：選 **Amazon Linux**（通常是「Amazon Linux 2023」，且標示「符合免費方案資格」）。
5. **執行個體類型（Instance type）**：選 **t2.micro 或 t3.micro**，認明旁邊有**「符合免費方案資格（Free tier eligible）」**字樣——這是不扣款的關鍵。
6. **金鑰對（Key pair）**：這次我們用免金鑰的連線方式，可以選**不使用金鑰對（Proceed without a key pair）**。
7. **網路設定**：保持**預設 VPC（Virtual Private Cloud，你帳號內建的虛擬網路）**、預設子網路即可，新手不用動。
8. **儲存設定**：維持預設的那顆小硬碟（免費額度內）即可。
9. 右側確認「數量 = 1」，按**啟動執行個體（Launch instance）**。
10. 回到執行個體清單，等**執行個體狀態**從 `Pending` 變成 **`Running`**，且**狀態檢查**通過。

:::note[🤔 為什麼每一步要這樣選？（入門白話）]
- **為什麼選 Amazon Linux？** 它是 AWS 自家、最省錢又最相容的 Linux，連 AWS CLI 都預先裝好，新手最不會卡關。
- **為什麼一定要 `t2.micro`／`t3.micro`？** 只有這種「符合免費方案」的小機型，在免費額度內**不扣錢**。選到別的機型就會開始計費——這是新手帳單爆掉的第一名原因。
- **為什麼可以「不使用金鑰對」？** 因為我們改用瀏覽器連線（下一段），不必自己保管 `.pem` 金鑰檔，少一個會弄丟、會外洩的東西。
- **為什麼放在預設 VPC／子網路？** 預設網路已經幫你設好「能上網、你連得進去」的基本規則，入門先不碰網路，專心體會「開機器」這件事就好。

**你預期會看到**：清單裡多出一列 `my-first-server`，狀態先是橘色的 `Pending`，約一兩分鐘後變成綠色的 **`Running`**，右邊「狀態檢查」顯示 `2/2 checks passed`。看到這個畫面就代表機器真的開起來了。
:::

### 連線進去（免自己管 SSH 金鑰）

不想處理 SSH 金鑰檔？AWS 提供兩種「瀏覽器就能連、較安全」的方式，二選一即可：

- **EC2 Instance Connect**：在執行個體清單勾選你的機器 → 右上角**連線（Connect）** → 選 **EC2 Instance Connect** 頁籤 → **連線**。瀏覽器就會跳出一個終端機畫面。
- **Session Manager**（屬於 Systems Manager）：同樣在**連線**畫面選 **Session Manager** 頁籤連入。它不需要對外開放連接埠，是實務上更推薦的安全做法（需要適當的 IAM 角色，進階時再深入）。

11. 連進去後，畫面出現類似這樣的 **Linux 提示字元**，就代表你成功了：

```bash
[ec2-user@ip-172-31-xx-xx ~]$
```

試著打個指令感受一下：

```bash
# 看看這台機器的主機名稱
$ hostname

# 看看它跑的是什麼系統
$ cat /etc/os-release
```

**你預期會看到**：`hostname` 會印出類似 `ip-172-31-xx-xx` 的一串名字；`cat /etc/os-release` 會印出好幾行系統資訊，裡面有 `Amazon Linux` 字樣。能印出東西，就代表你真的「進到那台機器裡面」下指令了。

🎉 恭喜，你剛剛親手開了一台在雲端的伺服器！

:::warning[🚑 常踩雷／常見誤解（EC2 這段）]
- **忘了選免費方案機型**：預設有時會跳到別的機型，一定要**親眼確認旁邊有「符合免費方案資格」**再開，否則第一分鐘就開始計費。
- **安全群組（防火牆規則）開太大**：如果你改走傳統 SSH、看到「來源」欄，**別填 `0.0.0.0/0`（等於對全世界開門）**。本篇用瀏覽器連線正是為了閃開這個雷——照做就不用碰安全群組。
- **只「停止」不「終止」**：等等清理時要選**終止（Terminate）**，不是停止（Stop）。停止只是關機，某些資源仍可能計費（詳見文末清理段）。
- **開了就忘**：這是最貴的雷。開了 EC2 卻忘記關，它會**一天 24 小時默默計費**，等收到帳單才發現已是數天後。做完務必回來清理。
:::

## 實作二：建立一個 S3 貯體並上傳檔案

目標：建一個你專屬的雲端倉庫，丟一個檔案上去、再抓回來。

1. 主控台搜尋列輸入 `S3` → 進入 S3 服務 → 點**建立貯體（Create bucket）**。
2. **貯體名稱（Bucket name）**：必須**全球唯一**。建議加上你的識別字和日期，例如 `my-first-bucket-wang-20261022`。（名稱只能小寫字母、數字和連字號）
3. **區域（Region）**：選跟你習慣用的同一個區域。
4. **封鎖公開存取（Block Public Access）**：**維持勾選「封鎖所有公開存取」——務必保持開啟！** 這是 S3 安全最重要的總開關，別為了「方便」把倉庫對全世界打開。
5. 其他設定維持預設 → 按**建立貯體**。

:::note[🤔 為什麼每一步要這樣選？（入門白話）]
- **為什麼貯體名稱要「全球唯一」還加日期？** S3 的名字是**全世界共用一個命名空間**，`test`、`mydata` 這種好名字早被別人用光了。加上你的識別字和日期，是最快取到一個沒人用過的名字的方法。
- **為什麼「封鎖所有公開存取」務必保持開啟？** 這是 S3 的安全總開關。關掉它，等於讓任何人都能從網路上看到你的檔案。現實中最常見的資料外洩，就是有人為了方便把這個關掉又忘了開回來。
- **為什麼先做私有倉庫，不先學「公開放網頁」？** 入門要先養成「預設就是私有、安全」的直覺；等觀念穩了，再去學什麼情況下才該刻意公開（而且會另外設權限）。

**你預期會看到**：建立成功後回到貯體清單，會看到你剛取的那個名字那一列，「存取」欄顯示 **`貯體和物件不公開（Bucket and objects not public）`**——看到「不公開」就對了。
:::

<Analogy title="🔒 為什麼不能把貯體設公開？">

把貯體設公開，就像把你家**倉庫大門拆掉、鑰匙掛在門口**——路過的任何人都能進去翻。現實世界最常見的雲端外洩事故，幾乎都是有人為了一時方便把 S3 設成公開然後忘了關。這也呼應了 AWS 的**責任共擔模型（Shared Responsibility Model）**：**AWS 負責「雲端本身」的安全，你負責「雲端裡面」資料的安全**——把貯體鎖好，是你的責任。

</Analogy>

### 上傳與下載

6. 點進你剛建的貯體 → **上傳（Upload）** → **新增檔案（Add files）** → 選一個電腦裡的小檔案（例如一張圖或一個文字檔）→ **上傳**。
7. 上傳完成後，在貯體裡會看到這個**物件（Object，也就是你的檔案）**。
8. 點進該物件 → 按**下載（Download）**，確認可以把檔案抓回電腦。

**你預期會看到**：上傳完成後貯體內多出一列你的檔名（這就是一個**物件**）；按下載後，瀏覽器會把同一個檔案存回你電腦，打得開、內容一樣，代表「上傳→保存→取回」整條路都通了。

成功了！你已經擁有一個私有、安全的雲端倉庫。

:::warning[🚑 常踩雷／常見誤解（S3 這段）]
- **把貯體設公開**：為了「快點看到檔案」而關掉「封鎖公開存取」，是新手最危險的一步。入門階段**完全不需要**公開，保持私有即可。
- **把重要資料放在「做完會刪掉」的地方**：這篇的貯體是**練習用、等等要刪掉的**。千萬別把唯一一份重要檔案（照片、報告）只放在這裡然後清理掉就不見了。練習請用隨便一個可丟的小檔案。
- **以為貯體「空的」才算乾淨**：貯體裡只要還有任何物件就**刪不掉**，而且還在佔用（極微量）儲存。清理時要**先清空物件、再刪貯體**（詳見文末清理段）。
:::

## 實作三（選配）：在 EC2 上用 CLI 存取 S3

這一步讓你體會**服務之間怎麼串接**——讓剛剛那台 EC2 直接存取你的 S3，完全不用輸入任何金鑰。

要做到「不用金鑰」，關鍵是幫 EC2 **掛上一個有 S3 權限的 IAM 角色（Role）**（例如 `AmazonS3ReadOnlyAccess`）。怎麼建角色、怎麼掛，[IAM 那篇](/saa/domain-1/iam)已經手把手教過，照著做即可。掛好角色後，回到 EC2 的終端機：

```bash
# 列出你帳號裡的 S3 貯體，憑證由 Role 自動提供，不用打金鑰
$ aws s3 ls

# 看看剛剛那個貯體裡有什麼（換成你的貯體名稱）
$ aws s3 ls s3://my-first-bucket-wang-20261022
```

**你預期會看到**：`aws s3 ls` 會列出你帳號裡的貯體（含剛剛建的那個）；第二個指令若貯體裡有檔案，會列出那個物件的時間與名稱。**全程你一個金鑰都沒打**——憑證是角色自動給的。

能列出貯體，代表「運算（EC2）」和「儲存（S3）」已經被你用安全的方式串起來了——這正是 SAA 考試最愛考的經典組合。

:::tip[💡 為什麼用角色、不寫死金鑰？]
把金鑰（Access Key）寫在程式或機器裡，外洩就等於把鑰匙交給別人。**IAM 角色提供的是會自動輪替的臨時憑證**，安全得多。考題只要看到「EC2 要存取 S3」，正解幾乎都是「建立 IAM 角色指派給 EC2」。
:::

## 最重要的一步：清理資源，避免被扣款

:::warning[🧹 做完一定要清理！不清理會持續扣款]
免費額度有**用量上限與時效**，忘了關的資源會在背景默默計費。請務必依序把這次開的東西全部清掉：

**1. 終止（Terminate）剛剛的 EC2 執行個體**
- 進 `EC2` → 執行個體清單 → 勾選 `my-first-server` → **執行個體狀態（Instance state）› 終止執行個體（Terminate instance）** → 確認。
- 注意是**終止（Terminate）**，不是只有**停止（Stop）**。「停止」只是關機，相關資源可能還在計費；**「終止」才是真正刪除整台機器**。
- **為什麼做完就要刪？** 免費額度是「每月固定時數」，開著不關很容易用超過上限、或額度到期後繼續計費。練習做完這台就沒用了，留著只有扣錢的風險、沒有好處——所以直接刪掉最安全。
- **你預期會看到**：狀態先變 `Shutting-down`，約一兩分鐘後變成 **`Terminated`**，再過一陣子這一列會自己從清單消失。看到 `Terminated` 就代表機器真的刪掉、不再計費了。

**2. 刪掉 S3 貯體（要先清空裡面的物件）**
- 進 `S3` → 點你的貯體 → 全選裡面的物件 → **刪除（Delete）**，按指示輸入確認字樣。
- 物件清空後，回到貯體清單 → 勾選該貯體 → **刪除（Delete）** → 輸入貯體名稱確認。
- （S3 貯體**必須先清空才能刪除**，這是正常流程。）
- **你預期會看到**：清空後物件清單變空；刪除貯體後回到清單，剛剛那個貯體名字**消失不見**，就代表刪乾淨了。

**3. 回帳單頁確認沒有持續產生費用**
- 主控台右上角帳號選單 → **帳單與成本管理（Billing and Cost Management）** → 看 **免費方案（Free Tier）** 使用量與目前帳單，確認沒有異常項目。
- **你預期會看到**：目前應付金額接近 `$0.00`，免費方案使用量都在上限內，沒有你不認得的服務在計費。

**忘了清理會怎樣？** 一台沒關的 EC2 一個月可能悄悄吃掉數美元到十幾美元；一堆沒刪的物件也會持續佔用儲存。它們不會跳出來提醒你，只會在月底帳單上出現。這就是為什麼「做完就清、並事先設好帳單告警」是入門最該養成的習慣。
:::

:::note
養成「**動手做完就清理**」的習慣，是每個 AWS 學習者最該先建立的肌肉記憶。這也是為什麼我們一開始就請你設好帳單告警——它是你的最後一道防線。
:::

<Cost title="💰 成本提醒">

這篇用的 `t2.micro`／`t3.micro` 與少量 S3 儲存都在**免費額度**內，照步驟做、做完清理，基本上不會產生費用。真正會讓人中招的，是**忘了終止 EC2 或忘了刪貯體**——它們會一直默默計費。記住：**資源開了就要記得關。**

</Cost>
