# 建立 AWS 帳號與安全初始設定

> 這篇帶完全沒碰過的新手，從零開好一個 AWS 帳號，並且在開好的第一時間就把「安全的鎖」裝好——這是最重要、也最容易被新手跳過的一步。

<Analogy title="🔑 比喻：剛拿到新家鑰匙，第一件事是什麼？">

你剛買下一間新房子，建商把鑰匙交給你。興奮之餘，**最該先做的不是搬家具，而是先把門鎖換好、裝好保全，而且那把能開全家每個房間的「總鑰匙」絕對不能隨便放、更不能天天帶在身上用。**

AWS 帳號一模一樣。開好帳號的那一刻，你手上就握有一把能動用整個帳號、刷爆你信用卡的「總鑰匙」。第一時間把安全設定做好，比急著去開服務重要一百倍。

</Analogy>

:::note[💬 閱讀小提示]
文章裡只要看到帶<Term desc="像這樣！滑鼠移到有虛線的名詞上（手機點一下），就會跳出白話解釋。">虛線底線的名詞</Term>，把滑鼠移上去就會跳出白話解釋。
:::

## 為什麼「第一步」最重要？

很多新手開好帳號就急著去玩各種服務，把安全設定擺到「以後再說」。問題是，AWS 帳號外洩的新聞層出不窮：有人把金鑰不小心推上 GitHub，幾小時內帳號就被拿去挖礦，月底收到幾十萬的帳單。

安全設定不是進階主題，而是**開帳號的第一天就該完成的基本功**。好消息是，這篇要教的設定**全部免費**，而且照著做半小時內就能搞定。

## 註冊帳號流程概述

註冊 AWS 帳號前，先準備好三樣東西：

| 需要什麼 | 說明與提醒 |
| --- | --- |
| **一個 email 信箱** | 這會是帳號的 <Term en="Root user" desc="帳號最高權限的使用者，用註冊時的 email 登入。">Root 使用者</Term>登入帳號。**請選一個你長期收得到信、不會停用的信箱**（別用公司可能收回的、或臨時信箱），將來重設密碼、收安全通知全靠它。 |
| **一張信用卡／金融卡** | AWS 會做一筆**小額驗證扣款**（通常 1 美元左右，之後會退回或自動沖銷），用來確認卡片有效。日常用量在<Term en="Free Tier" desc="AWS 提供新手一定額度免費使用的方案，超過才計費。">免費方案</Term>內通常不會真的扣錢。 |
| **一支手機** | 註冊過程會用簡訊或語音做**電話驗證**，確認你是真人。 |

註冊流程大致是：到 AWS 官網點「建立帳號」→ 填 email 與帳號名稱 → 填聯絡與付款資料 → 完成電話驗證 → 選一個支援方案（選**免費的 Basic** 即可）。整個流程跟著畫面走，約 10 分鐘完成。

:::tip[💡 小提醒]
帳號名稱、聯絡資料將來都能改，不用太糾結。唯一要慎重的是**那個 email**——它綁定你的 Root 使用者，換起來很麻煩。
:::

## Root 使用者有多危險？

註冊完成的那一刻，系統會自動建立一個 <Term en="Root user" desc="用註冊 email 登入、擁有帳號最高權限、無法被任何權限政策限制的使用者。">Root 使用者</Term>——就是你剛才用來註冊的那個 email。

**Root 使用者擁有這個帳號的最高權限，能做任何事**：關掉所有服務、刪光所有資料、改付款方式、甚至關閉整個帳號。而且**沒有任何權限政策能限制它**。

<Analogy title="🏢 回到大樓比喻">

如果把 AWS 帳號想成一棟大樓，**Root 使用者就是建這棟樓、擁有萬能鑰匙的大老闆**。這把鑰匙能開每一道門、每一個保險箱。正因為太萬能，平常辦公絕對不能用它——萬一弄丟或被偷，整棟樓就不是你的了。

</Analogy>

:::warning[🚨 Root 外洩 = 整個帳號被接管]
一旦 Root 的帳號密碼外洩，別人就能**完全接管你的帳號**：盜用運算資源去挖礦（帳單爆表）、刪光你的資料、把你自己鎖在門外。**所以接下來最重要的事，就是先幫 Root 加上一道額外的鎖，並且從此不再用 Root 做日常操作。**
:::

## 🔒 開帳號後「立刻要做」的安全清單

這是本篇的重點。剛開好帳號、還沒去碰任何服務之前，請**依序**完成下面四件事。全部免費。

### 步驟 1：為 Root 開啟 MFA（多因素驗證）

<Term en="Multi-Factor Authentication" desc="登入時除了密碼，還要再輸入一組手機 App 產生的動態驗證碼，多一道鎖。">MFA（多因素驗證，Multi-Factor Authentication）</Term> 的意思是：登入時**光有密碼還不夠，還要再輸入一組手機上動態產生的 6 位數驗證碼**。這樣就算密碼被偷，對方沒有你的手機也進不來。這是保護 Root 最有效、最該優先做的一步。

:::info[🤔 為什麼「一建好帳號就要」幫 Root 開 MFA？]
因為 Root 是整個帳號唯一「關不掉、擋不住」的最高權限，而**密碼本身很脆弱**——可能被猜中、被外洩的其他網站密碼連帶破解、或在釣魚網站被騙走。只靠密碼等於整個帳號只有一道鎖。

早一秒開 MFA，就早一秒多上一道「光偷到密碼也沒用」的鎖。這件事**只要做一次、完全免費、半分鐘搞定**，換來的卻是「帳號被接管」這種最嚴重風險的大幅下降。越早做越划算——別等「哪天有空再說」，因為被盜往往就發生在那個「還沒設定」的空窗期。
:::

#### 🛠️ 動手做：幫 Root 開啟 MFA

1. 先在手機上安裝一款驗證器 App（例如 Google Authenticator 或 Microsoft Authenticator）
2. 用 Root 的 email 登入 AWS 主控台
3. 右上角點你的帳號名稱 → 選 **安全憑證（Security credentials）**
4. 找到 **多重要素驗證 (MFA)** 區塊 → 點 **指派 MFA 裝置（Assign MFA device）**
5. 選 **驗證器應用程式（Authenticator app）** → 用手機 App 掃描畫面上的 QR Code
6. App 會開始跳動 6 位數驗證碼，**連續輸入兩組**（系統要確認時間同步）→ 完成

從此 Root 登入時，除了密碼還會要求輸入 App 上的驗證碼。

:::tip[💡 保管好備援]
把驗證器 App 綁在你隨身的手機上，並留意 App 本身的備份／雲端同步機制。萬一手機遺失卻沒有備援，救回 Root 會很麻煩。
:::

### 步驟 2：建立一個日常用的 IAM 管理員身分

幫 Root 上好鎖之後，第二件事是：**從今以後不要再用 Root 做日常操作**。那要用什麼？建立一個專屬的「日常管理員」身分來用。

你有兩種做法：

- **做法 A（傳統、最直覺）：建立一個 <Term en="Identity and Access Management" desc="AWS 管理「誰能對哪些資源做哪些操作」的服務，完全免費。">IAM</Term> 使用者**，給它管理員權限，之後都用這個 IAM 使用者登入。
- **做法 B（AWS 現在的建議）：啟用 <Term en="IAM Identity Center" desc="AWS 集中管理登入身分的服務，提供統一入口與更好的多帳號管理，前身為 AWS SSO。">IAM Identity Center</Term>**，用它建立你的日常登入身分。它提供統一的登入入口，將來要管理多個帳號或多位成員時更方便。

對只有單一帳號的新手，**做法 A 最快上手**，下面就帶你做一次。

:::info[🤔 為什麼要「另建 IAM 管理員」，而不是天天用 Root？]
Root 太萬能，所以「平常不用它」本身就是一種保護。理由很白話：

- **減少曝險**：你每天登入、在咖啡廳連網、裝瀏覽器外掛……用得越頻繁，憑證被偷、被釣魚的機會越大。日常改用權限較小的 IAM 身分，就算這個身分被盜，**災情也有上限**（還能用 Root 把它停掉、善後）；但 Root 一旦外洩就是整個帳號全沒。
- **可控、可收回**：IAM 身分可以隨時停用、刪除、改權限、分給不同人、各自開 MFA、查操作紀錄；Root 做不到這些精細管理。
- **養成好習慣**：日常都用 IAM，自然就不會手滑用 Root 做危險操作。Root 只在「改付款方式、關閉帳號」這種**非它不可**的極少數場合才拿出來。

一句話：**把 Root 鎖進保險箱，日常用一把「弄丟了也補得回來、權限還能收回」的員工鑰匙。**
:::

#### 🛠️ 動手做：建立一個日常用的 IAM 管理員

1. 用 Root 登入主控台 → 搜尋列輸入 `IAM` → 進入 IAM 服務
2. 左側點 **使用者（Users）** → **建立使用者（Create user）**
3. 取一個好記的名字（例如 `my-admin`），勾選 **提供使用者對 AWS 管理主控台的存取權**
4. 權限設定：選 **直接連接政策（Attach policies directly）** → 勾選 `AdministratorAccess`
5. 建立完成後，**也幫這個 IAM 使用者開啟 MFA**（步驟同上，在該使用者的安全憑證頁面設定）
6. 登出 Root，改用這個 IAM 使用者的登入網址與帳密登入

<Analogy title="🔑 為什麼要多這一步？">

這就像大老闆（Root）給自己辦了一張「員工管理證」（IAM 管理員）。平常上班刷這張員工證就夠用，萬能的總鑰匙（Root）鎖進保險箱，只有「改付款方式、關閉帳號」等極少數非它不可的事才拿出來用。

</Analogy>

:::warning[⚠️ 關於「最小權限」]
這裡為了新手方便給了 `AdministratorAccess`（管理員全權）。但請記住 AWS 安全的核心觀念——**最小權限原則（least privilege）**：只給「完成工作所需的最小權限」。等你熟悉之後，應該為不同用途建立權限更精準的身分，而不是什麼都給管理員。**Root 更是要少用到幾乎不用。**
:::

### 步驟 3：設定帳號別名、選好主要工作 Region

這一步讓你之後的操作更順手。

**設定帳號別名（Account Alias）**：預設登入 IAM 使用者時，網址裡是一長串 12 位數字的帳號 ID，很難記。你可以設一個好記的**帳號別名**來取代它。

#### 🛠️ 動手做：設定帳號別名

1. 進入 **IAM** 服務 → 左側 **儀表板（Dashboard）**
2. 找到 **AWS 帳戶（AWS Account）** 區塊的帳戶別名 → 點 **建立／編輯**
3. 設一個全球唯一的別名（例如 `mika-lab`），登入網址就會變成好記的 `mika-lab.signin.aws.amazon.com`

**選好主要工作 Region**：<Term en="Region" desc="AWS 在全球各地的機房所在地理區域，例如東京、首爾、維吉尼亞北部。">Region（區域）</Term> 是 AWS 機房所在的地理位置。建議挑一個**離你或你的使用者最近的區域**當主要工作區（台灣使用者常選東京 `ap-northeast-1` 或首爾 `ap-northeast-2`，延遲較低）。主控台右上角可以切換，之後開服務請留意目前停在哪個 Region。

:::note[📌 為什麼要留意 Region？]
很多新手困惑「我的資源怎麼不見了？」——其實多半是**切到了別的 Region**。資源是分 Region 存放的，養成固定在同一個 Region 工作的習慣能避免很多混亂。
:::

### 步驟 4：（預告）設定帳單告警

最後還有一件保命的事：**設定帳單告警**，讓花費超過你設定的門檻時自動寄信通知你，避免月底收到驚嚇帳單。這部分內容較多，我們放到下一篇專門講。

:::warning[🚑 常踩雷/常見誤解]
以下四件是新手最常中招、也最容易出事的地方，請務必避開：

- **用 Root 做日常操作**：覺得「我自己的帳號，用 Root 最方便」。這是最危險的習慣——Root 一旦被盜就是整個帳號淪陷。開好 IAM 管理員後就**登出 Root，日常只用 IAM 身分**。
- **Root 沒開 MFA**：以為「我密碼夠長夠複雜就安全了」。密碼再強，被釣魚或外洩就破功。**Root 沒開 MFA 等於整個帳號只有一道鎖**，務必第一時間補上。
- **把 <Term en="Access key" desc="程式／CLI 存取 AWS 用的一組金鑰，等同帳號密碼，外洩同樣危險。">存取金鑰（access key）</Term>外流、或直接寫進程式**：把金鑰硬寫進程式碼、推上 GitHub、貼到聊天室，是帳號被挖礦的頭號原因。**金鑰等同密碼，絕不寫進程式、不進版控**（之後用 Role、環境變數等更安全的方式，後面會教）。真的外流了就**立刻停用該金鑰**。
- **沒設帳單警示**：以為「在免費方案內就不會被扣錢」。一旦誤開了收費服務、或帳號被盜拿去挖礦，沒有警示你會到**月底才發現**。花一次功夫設好門檻通知，就能把「驚嚇帳單」擋在前面（下一篇教）。
:::

## 和考試的關聯

你剛剛做的這些事——Root 保護、MFA、IAM 使用者、最小權限——正是 SAA（解決方案架構師）考試**安全領域（Domain 1）**反覆考的核心觀念。考試常出「哪種做法最符合安全最佳實務？」這類題目，而「**不要用 Root 做日常操作、開啟 MFA、遵循最小權限**」幾乎是標準答案。IAM 還有 Group、Policy、Role 等更進階的用法，之後在安全領域會深入介紹。

**先把今天這些做好，你不只保護了自己的帳號，也等於提前把考試最愛考的安全觀念練成了肌肉記憶。**
