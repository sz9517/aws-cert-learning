# 實驗 1：建立你的第一個 VPC

> 這個實驗要你**親手建一個 VPC**——也就是你在 AWS 上專屬的一塊虛擬網路。為什麼從它開始？因為**網路是所有架構的地基**：你之後開的每一台伺服器、每一個資料庫，都得先住在某個網路裡。把這塊地基搞懂，後面的高可用、安全設計才站得穩。

<Vocab title="📌 先認識這篇會出現的名詞（完全沒碰過也能懂）">

- **VPC（Virtual Private Cloud）**：你在 AWS 上「**自己圈起來的一塊虛擬網路**」，裡面的資源彼此看得到、對外則由你決定要不要開門。
- **子網路（Subnet）**：VPC 裡再切出來的**小區塊**，每個子網路只屬於一個可用區域。
- **CIDR**：描述一段 IP 位址範圍的寫法，例如 `10.0.0.0/16` 代表一大段可用的內部 IP。
- **路由表（Route Table）**：決定「往哪個目的地的流量，該走哪條路」的**交通規則表**。
- **網際網路閘道（IGW，Internet Gateway）**：VPC 通往公共網際網路的**大門**。
- **可用區域（AZ，Availability Zone）**：同一個區域裡彼此獨立的機房，分開放可以避免單點故障。

</Vocab>

:::note[💬 閱讀小提示]
看到帶<Term desc="像這樣！滑鼠移到有虛線的名詞上（手機點一下），就會跳出白話解釋。">虛線底線的名詞</Term>，把滑鼠移上去就會跳出白話解釋。所有名詞也整理在 [名詞與服務對照表](/glossary)。
:::

:::info[開始前的前提]
這篇假設你已經完成前面的準備：

- 已經完成入門的**第一個動手實作（EC2 + S3）**，對主控台的操作有基本手感。
- 已經**設好帳單告警（Billing Alarm）**，花超過門檻會收到通知。
- 知道怎麼在主控台右上角**切換區域（Region）**——建議整篇都固定在同一個區域（例如「亞太區域（東京）ap-northeast-1」）。

還沒做完？先回頭補完再來，這些是你的安全網。
:::

## 先搞懂：VPC 到底是什麼、為什麼要分

<Analogy title="🏘️ 生活比喻：VPC 就像一塊你自己的社區用地">

- **VPC** = 你向 AWS 圈下來的**一整塊社區土地**（用 CIDR 標出邊界，例如 `10.0.0.0/16`）。
- **子網路** = 這塊地上劃出的**不同街區**：有的街區臨大馬路、對外開放（公有），有的街區藏在裡面、只給內部用（私有）。
- **路由表** = 每個街區門口的**路標**，告訴車子「要出社區請走這條路」。
- **網際網路閘道（IGW）** = 社區通往外面大馬路的**唯一大門**。沒有這道門，車子開到邊界就出不去。

</Analogy>

**公有子網路 vs 私有子網路**，差別只在一件事：**它的路由表有沒有一條指向 IGW 的路**。

- **公有子網路**：路由表裡有一條「往網際網路（`0.0.0.0/0`）走 IGW」的規則，裡面的資源若配上公有 IP，就能直接對外，也能被外面連進來。適合放對外的 Web 伺服器。
- **私有子網路**：沒有通往 IGW 的路，外面連不進來。適合放資料庫、後端服務這類**不該直接暴露在網際網路上**的東西。

<Term en="Virtual Private Cloud" desc="你在 AWS 上自己圈起來的一塊虛擬網路，裡面的資源彼此相通，對外由你決定要不要開門。">為什麼要分公有和私有？</Term>一句話：**把該對外的放外圈、不該對外的鎖內圈**，這就是最基本的網路安全分層。資料庫被鎖在私有子網路，就算有人攻進你的 Web 伺服器，也沒辦法從網際網路直接摸到資料庫。

## 動手做：從零建一個 VPC

目標：建一個 VPC，裡面有**一個公有子網路**和**一個私有子網路**，並讓公有子網路能對外上網。

:::info[🧭 動手前先想清楚：為什麼是這個設計]
為了讓每一步都「知其所以然」，先把這次的規劃講白：

- **為什麼切一個公有、一個私有？** 這是最小可用的「分層」示範：**對外的放公有、不該對外的放私有**。真實架構裡 Web 伺服器放公有、資料庫放私有，攻進 Web 也摸不到資料庫。
- **為什麼 VPC 用 `/16`、子網路用 `/24`？** `/16` 給你 65,536 個內部 IP（一大塊地），之後要再切很多子網路都夠；每個 `/24` 子網路約 250 個可用 IP，對單一用途綽綽有餘。**先規劃大、再切小**，避免之後地不夠用又難改。
- **為什麼兩個子網路要跨不同 AZ？** 單一 AZ 若整座機房出事，你的服務就全倒；**跨 AZ 才能做高可用**，這是後面所有多 AZ 架構的前提。
- **為什麼公有要 IGW、公有路由表要指向它？** IGW 是 VPC 對外的唯一大門；**光有門還不夠，還要在路由表「畫一條路」指向它**，流量才知道「要出去走這扇門」。少了這條路，子網路就算有公有 IP 也出不去。
:::

AWS 主控台提供一個很貼心的精靈叫 **VPC and more**，它能**一次幫你把 VPC、子網路、路由表、IGW 全部建好並接起來**。我們先用精靈快速建一次（了解它幫你做了什麼），再說明手動時每一步各是什麼。

### 做法 A：用「VPC and more」精靈一次搞定（推薦新手）

1. 登入 AWS 主控台 → 確認右上角的**區域**是你要用的那個 → 搜尋列輸入 `VPC` → 進入 VPC 服務。
2. 點**建立 VPC（Create VPC）**。
3. 最上方選擇 **VPC 等（VPC and more）**——這會開啟精靈模式。
4. **名稱標籤（Name tag）**：填一個好認的前綴，例如 `my-first-vpc`。
5. **IPv4 CIDR 區塊**：填 `10.0.0.0/16`（這給你很大一段內部 IP 可用）。
6. **可用區域（AZ）數量**：選 **2**（跨兩個 AZ，是高可用的基本盤）。
7. **公有子網路數量**：選 **2**；**私有子網路數量**：選 **2**。（精靈會自動把它們分散到不同 AZ。）
8. **NAT 閘道（NAT gateways）**：為了避免額外計費，這次選 **無（None）**。（NAT 閘道會收費，等你之後需要讓私有子網路對外時再建。）
9. **VPC 端點（VPC endpoints）**：選 **無（None）** 即可。
10. 右側的**預覽圖**會即時畫出它要幫你建的東西 → 確認無誤後按**建立 VPC（Create VPC）**。

精靈跑完後，它其實幫你一次建好了這些：**1 個 VPC + 公有/私有子網路（跨 2 個 AZ）+ 1 個網際網路閘道並附加到 VPC + 一張公有路由表（含指向 IGW 的 `0.0.0.0/0` 規則）+ 一張私有路由表**，而且把對應的子網路都關聯好了。你現在就有一塊可用的網路地基了。

### 做法 B：手動建一次，徹底搞懂每個零件

如果你想真正理解精靈在背後做了什麼，照這個順序手動做一次最有感：

1. **建立 VPC**：VPC 服務 → 左側**您的 VPC（Your VPCs）** → **建立 VPC** → 選「僅 VPC」→ 名稱 `my-first-vpc`、IPv4 CIDR `10.0.0.0/16` → 建立。
   - **為什麼先建這個？** VPC 是「外框」，子網路、路由表、IGW 都得掛在某個 VPC 底下，所以它一定最先建。
   - **預期會看到**：VPC 清單多一筆 `my-first-vpc`，狀態 `Available`，並且 AWS 已自動替它建好一張「主要路由表（main）」——這張預設只有 VPC 內部互通的規則，**沒有**對外的路。
2. **建立公有子網路**：左側**子網路（Subnets）** → **建立子網路** → 選剛剛的 VPC → 名稱 `public-1a`、選一個 AZ（例如 `ap-northeast-1a`）、CIDR `10.0.1.0/24`。
   - **為什麼 CIDR 是 `10.0.1.0/24`？** 它必須落在 VPC 的 `10.0.0.0/16` 範圍「之內」，且**不能和其他子網路重疊**；`.1.` 這段是我們留給公有用的，等等私有用 `.2.`，一看就分得清。
   - **預期會看到**：子網路清單多一筆 `public-1a`，所在 AZ 是你剛選的那個。此時它**還不是真正的「公有」**——要等第 5、6 步把路由接上去才算。
3. **建立私有子網路**：同樣流程，名稱 `private-1c`、選**另一個 AZ**（例如 `ap-northeast-1c`，跨 AZ 是為了高可用）、CIDR `10.0.2.0/24`。
   - **為什麼刻意選另一個 AZ？** 讓公有、私有分散在不同機房，是最省力就能拿到的高可用；真實架構裡你會在每個 AZ 各放一組公有+私有。
   - **為什麼它「不用」做任何路由設定就自動是私有？** 因為私有的定義就是「路由表沒有通往 IGW 的路」——我們**什麼都不接**，它自然就對外封閉。
   - **預期會看到**：子網路清單再多一筆 `private-1c`，AZ 和 `public-1a` 不同。
4. **建立並附加 IGW**：左側**網際網路閘道（Internet Gateways）** → **建立網際網路閘道** → 命名後建立 → 選取它 → **動作 › 連接至 VPC（Attach to VPC）** → 選你的 VPC。
   - **為什麼建完還要「附加」到 VPC？** 剛建好的 IGW 是「沒接上任何 VPC」的孤兒，狀態是 `Detached`；**附加後才真的成為那個 VPC 的對外大門**。少了這步，後面路由表指向它也沒用。
   - **預期會看到**：IGW 狀態從 `Detached` 變成 `Attached`，並顯示它附加到的 VPC ID。
5. **建立公有路由表並加路由**：左側**路由表（Route Tables）** → **建立路由表** → 選你的 VPC、命名 `public-rt` → 建好後進入該路由表 → **路由（Routes）› 編輯路由 › 新增路由** → 目的地填 `0.0.0.0/0`、目標選你的 **IGW** → 儲存。
   - **為什麼路由要這樣設？** `0.0.0.0/0` 是「所有目的地（也就是整個網際網路）」的寫法；這條規則白話講就是「**要去外面的流量，一律走 IGW 這扇門**」。這正是「公有子網路」和「私有子網路」唯一的差別所在。
   - **為什麼另外建一張，不直接改預設的主要路由表？** 改到主要路由表會讓**所有沒另外指定的子網路都變公有**，容易把本該私有的也一起開門；**公有專用一張、私有維持預設**，分得乾淨又不易出錯。
   - **預期會看到**：`public-rt` 的路由清單裡有兩條——一條 VPC 內部的 `10.0.0.0/16 → local`（本來就有，刪不掉），以及你新增的 `0.0.0.0/0 → igw-xxxx`。
6. **把公有子網路關聯到公有路由表**：在 `public-rt` 的**子網路關聯（Subnet associations）** → **編輯子網路關聯** → 勾選 `public-1a` → 儲存。（私有子網路不要關聯這張表，它就保持私有。）
   - **為什麼還要「關聯」這一步？** 路由表建好不會自動套到任何子網路；**要明確關聯，那張「有對外路」的表才會真正作用在 `public-1a` 上**，它才正式變公有。
   - **預期會看到**：`public-rt` 的子網路關聯列出 `public-1a`；而 `private-1c` 仍關聯在**主要路由表**（沒有對外路），維持私有。

做法 B 做完的結果，和精靈建出來的核心完全一樣——差別只在精靈幫你一次點完所有按鈕。

## 選配：在公有子網路開一台 EC2 驗證能上網

想親眼確認公有子網路真的通？開一台最小規格的 EC2 試試：

1. 進 `EC2` → **啟動執行個體（Launch instance）** → 名稱 `vpc-test` → AMI 選 **Amazon Linux**（符合免費方案資格）。
2. **執行個體類型**選 **t2.micro 或 t3.micro**（認明「符合免費方案資格」字樣）。
3. **網路設定** → **編輯** → **VPC** 選你剛建的 `my-first-vpc`、**子網路**選**公有子網路**（例如 `public-1a`）→ **自動指派公有 IP** 設為**啟用（Enable）**。
4. 安全群組可用預設，啟動執行個體。
5. 用 **EC2 Instance Connect** 連進去（瀏覽器就能連，不必管金鑰），在終端機測試對外連線：

```bash
# 能印出外部 IP，就代表這台機器真的能連到網際網路
$ curl -s https://checkip.amazonaws.com
# 預期會看到：一組公有 IP，例如
# 54.xxx.xxx.xxx

# 或簡單 ping 一下外部網站（Ctrl+C 停止）
$ ping -c 3 aws.amazon.com
# 預期會看到：連續 3 行 "64 bytes from ..."、延遲（time=xx ms），最後 0% packet loss
```

:::note[👀 把「自動指派公有 IP」設為啟用，為什麼很關鍵]
上面第 3 步一定要把**自動指派公有 IP** 開成**啟用（Enable）**。為什麼？因為「公有子網路有通往 IGW 的路」只是「門開著」；**機器自己還要有一個公有 IP，才有辦法真的走出那扇門**。兩者缺一就連不出去——這也是初學者最常卡的地方之一。
:::

## 怎麼算成功？

- VPC 清單裡看得到 `my-first-vpc`，狀態為 `Available`。
- 子網路清單裡有**兩個公有、兩個私有**（做法 B 則是各一個），且分散在**不同 AZ**。
- 公有路由表裡有一條 `0.0.0.0/0 → igw-xxxx` 的路由；私有路由表**沒有**這條。
- （選配）那台 EC2 能成功 `curl` 到外部 IP——這代表「公有子網路 + IGW + 路由表」整條路真的通了。

🎉 恭喜，你已經親手打造了一塊有公有和私有分層的雲端網路！

---

:::warning[🚑 常踩雷：這四個坑新手幾乎都中過]
- **NAT 閘道忘了刪，帳單一直跳。** NAT 閘道**只要存在就按小時計費**（即使沒流量），一個月可達二三十美元。這次我們刻意選「無」；萬一你手滑建了，**務必**到 VPC → NAT 閘道把它刪掉，而且**連帶刪掉它用的彈性 IP（Elastic IP）**——沒綁到執行中資源的彈性 IP 也會收費。
- **路由表沒設好，怎樣都連不出去。** 兩個最常見原因：一是**忘了在公有路由表加 `0.0.0.0/0 → IGW` 那條**；二是**忘了把公有子網路「關聯」到這張表**（第 6 步），結果子網路還掛在沒有對外路的主要路由表上。連不出去時，第一個就檢查這兩點。
- **CIDR 規劃不當，之後很難救。** 子網路 CIDR **必須落在 VPC 範圍內、且彼此不重疊**；VPC 的 CIDR 建好後**不能縮小、也不能隨意改**。別一開始就把 VPC 切太小（例如用 `/24`），不然之後要加子網路會沒 IP 可用。寧可先用 `/16` 這種大範圍。
- **安全群組／NACL 把自己擋在外面。** 就算路由全對，**安全群組（Security Group）或網路 ACL（NACL）擋掉流量，照樣連不上**。連不進 EC2 時，確認安全群組的**輸入規則（Inbound）** 有放行你要的連線（EC2 Instance Connect 需要對應來源的連線）；NACL 是「連子網路層級」的防火牆，預設全通，但若你改過它，記得它**要同時放行來回兩個方向**（它不像安全群組會自動記住回程）。
:::

:::warning[🧹 做完一定要清理！不清理 NAT／EIP 等資源會持續扣款]
VPC 本身不收費，但這個實驗牽涉到的**部分資源會計費**（例如若你誤建了 NAT 閘道，或 EC2 忘了關）。請務必依序清掉：

**1. 先終止（Terminate）測試用的 EC2**
- 進 `EC2` → 勾選 `vpc-test` → **執行個體狀態（Instance state）› 終止執行個體（Terminate instance）** → 確認。
- 注意是**終止（Terminate）**而非只有**停止（Stop）**；狀態變成 `Terminated` 才算真的刪掉。

**2. 刪除 VPC（精靈建立的相關資源會一併刪除）**
- 進 `VPC` → **您的 VPC（Your VPCs）** → 勾選 `my-first-vpc` → **動作 › 刪除 VPC（Delete VPC）**。
- 若你是用 **VPC and more** 精靈建的，刪除時主控台會**列出並一併刪掉**它當初幫你建的子網路、路由表、IGW 等相關資源——照提示輸入 `delete` 確認即可。
- 若是做法 B 手動建的，刪 VPC 前可能要先手動分離並刪除 IGW，依主控台提示處理。

**3. 回帳單頁確認不再計費**
- 主控台右上角帳號選單 → **帳單與成本管理（Billing and Cost Management）** → 檢查**免費方案（Free Tier）** 使用量與目前帳單，確認沒有 NAT 閘道、彈性 IP 或 EC2 這類還在計費的項目。
:::

<Cost title="💰 成本提醒">

**VPC、子網路、路由表、網際網路閘道本身都不收費。** 這個實驗真正可能扣款的地方有兩個：一是**NAT 閘道**（會按小時和流量收費，所以我們這次刻意選「無」），二是**忘了終止的 EC2**。只要照步驟把 NAT 設為「無」、做完乖乖清理，基本上不會產生費用。記住：**資源開了就要記得關。**

</Cost>

## 這對考試的意義

別小看這塊網路地基——**VPC 是 SAA 考試 Domain 1（安全）和 Domain 2（高可用與韌性）的共同底座**：

- **安全（D1）**：把資料庫、後端鎖進**私有子網路**，只讓 Web 層放在公有子網路，是「最小暴露面」的經典做法。考題常考「資料庫不該有公有 IP」「哪些東西該放私有子網路」。
- **高可用（D2）**：把子網路**跨多個 AZ** 分散，是幾乎所有高可用架構（多 AZ 部署、負載平衡、資料庫備援）的前提。考題一看到「提高可用性／容錯」，答案往往就牽涉到跨 AZ 的子網路設計。

把 VPC 練熟，等於同時替這兩個考試領域打好了共同底子。
