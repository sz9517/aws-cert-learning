# Domain 1 原創練習題（仿官方考題風格）

先自己點選答案，再按「**顯示答案與解析**」。題目對齊官方考試領域與題型風格，為**原創**內容。

<Quiz
  qnum={1}
  total={3}
  question="你的應用程式跑在 EC2 上，需要讀取 S3 的檔案。以下哪個做法最符合 AWS 安全最佳實務？"
  options={[
    '把 Access Key 和 Secret Key 直接寫在程式碼裡',
    '把金鑰存在 EC2 的環境變數',
    '建立一個 IAM Role 並指派給 EC2 執行個體',
    '用 Root 使用者的金鑰',
  ]}
  answer={2}>

**正解：C**

EC2 應透過 **IAM Role** 取得臨時、會自動輪替的憑證，完全不需要在任何地方儲存長期金鑰，風險最低。

A、B、D 都把長期金鑰暴露在可能外洩的位置；尤其 D 使用 Root 金鑰違反最小權限原則，是最嚴重的錯誤做法。

</Quiz>

<Quiz
  qnum={2}
  total={3}
  question="一間公司希望「工程部」10 位成員都擁有相同的 AWS 權限，未來新人加入也能快速套用。最有效率的管理方式是？"
  options={[
    '為每個人各自附加一份相同的 Policy',
    '建立一個 IAM Group，把 Policy 綁在 Group 上，再把成員加入',
    '共用同一組 IAM User 帳號密碼',
    '給每個人 Root 權限',
  ]}
  answer={1}>

**正解：B**

把權限綁在 **IAM Group**，成員加入群組即自動取得權限，新人上手快、權限統一好維護。

A 可行但要逐一維護、容易出錯；C 共用帳號無法稽核是誰做的，屬安全大忌；D 嚴重違反最小權限。

</Quiz>

<Quiz
  qnum={3}
  total={3}
  question="安全團隊要求：就算某個 Policy 允許了某操作，也必須能「強制禁止」特定高風險動作。IAM 的權限評估邏輯是？"
  options={[
    'Allow 一定勝過 Deny',
    '明確的 Deny 一定勝過任何 Allow',
    '看哪個 Policy 比較晚建立',
    '兩者衝突時全部忽略',
  ]}
  answer={1}>

**正解：B**

IAM 評估規則：**預設全部拒絕 → 有 Allow 才放行 → 但只要出現明確 Deny，就一律擋下**。所以 Deny 永遠是最後防線，勝過一切 Allow。這是考試超高頻考點！

</Quiz>

正式上線後，這個領域的題庫會擴充到約 15～30 題，涵蓋 IAM、加密、網路安全等主題。
:::
