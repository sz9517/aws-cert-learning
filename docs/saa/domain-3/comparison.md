# Domain 3 服務比較與考前速查

> 這一頁把 Domain 3（高效能架構）裡**最容易混淆**的服務整理成比較表，考前快速掃一遍最有效率。每張表後面都附一句「**考試怎麼選**」的決策提示——看到題幹的關鍵字，就能直接對應到答案。

:::tip[怎麼用這頁]
高效能的題目幾乎都在考「**選型取捨**」：同樣能解決問題的選項擺一起，用「最高效能／最低延遲／最高吞吐／最少營運負擔」這類限定詞逼你選。記住每個服務「只有它能做」的那一格，就是判別點。
:::

## 1. EC2 vs Lambda vs Fargate（三種運算方式）

| 比較項目 | EC2 | Lambda | Fargate |
|---|---|---|---|
| 你要管什麼 | 整台虛擬機（OS、修補） | 什麼都不用管 | 容器，不用管節點 |
| 計費方式 | 按執行個體時間 | 按呼叫次數＋執行毫秒 | 按容器 vCPU／記憶體用量 |
| 執行時間 | 不限 | 單次最長 15 分鐘 | 不限 |
| 適合 | 長時間、穩定負載、需完整控制 | 短任務、事件驅動、流量起伏大 | 容器化應用、不想管伺服器 |
| 冷啟動 | 無 | 有（閒置後首次較慢） | 幾乎無 |

**考試怎麼選**：題幹講「**不想管伺服器／按用量付費／事件觸發的短任務**」→ **Lambda**；「**需要完整 OS 控制／長時間執行／特殊軟體**」→ **EC2**；「**已經容器化，但不想管底層 EC2 節點**」→ **Fargate**。

## 2. EBS vs 執行個體儲存 vs EFS vs FSx（四種儲存）

| 比較項目 | EBS | 執行個體儲存 | EFS | FSx |
|---|---|---|---|---|
| 類型 | 區塊儲存（單台掛載） | 區塊儲存（實體直連） | 檔案系統（NFS 共享） | 檔案系統（SMB／Lustre） |
| 可多台共享 | 否（io2 可多重掛載少數台） | 否 | **是（多台 Linux 同時掛）** | 是 |
| 關機後保留 | **是（持久）** | ❌ 消失（暫存） | 是 | 是 |
| 效能特性 | gp3 均衡／io2 最高 IOPS | **極高 IOPS（本機）** | 自動擴展吞吐 | Lustre 極高吞吐 |
| 典型用途 | 一般開機碟、資料庫 | 暫存快取、臨時高速碟 | Linux 共享檔案 | Windows 檔案共享／HPC |

**考試怎麼選**：「**最高 IOPS 的關鍵資料庫**」→ **io2 Block Express**；「**大檔循序、便宜吞吐**」→ **st1**；「**多台 Linux 同時共享檔案**」→ **EFS**；「**Windows SMB 檔案共享**」→ **FSx for Windows**；「**HPC 超高吞吐暫存**」→ **FSx for Lustre 或執行個體儲存**；看到「**資料關機後要保留**」就**不能選執行個體儲存**。

## 3. RDS vs Aurora vs DynamoDB（三種資料庫）

| 比較項目 | RDS | Aurora | DynamoDB |
|---|---|---|---|
| 資料模型 | 關聯式（SQL） | 關聯式（相容 MySQL/PostgreSQL） | NoSQL（鍵值／文件） |
| 效能 | 標準 | **約 RDS 數倍、儲存自動擴展** | **個位數毫秒、幾乎無限擴展** |
| 擴展讀取 | Read Replica | Read Replica（最多 15 個） | 自動分區＋DAX 快取 |
| 營運負擔 | 託管 | 託管（更自動） | **無伺服器** |
| 典型用途 | 一般關聯式應用 | 高效能關聯式、企業級 | 超大規模、低延遲鍵值查詢 |

**考試怎麼選**：「**要標準 SQL／關聯式／託管**」→ **RDS**；「**比 RDS 更高效能的關聯式、企業級**」→ **Aurora**；「**超大規模、個位數毫秒、無伺服器彈性**」→ **DynamoDB**；「**讀取流量拖垮主庫**」→ 加 **Read Replica**。

## 4. ElastiCache Redis vs Memcached vs DAX（快取）

| 比較項目 | Redis | Memcached | DAX |
|---|---|---|---|
| 資料結構 | 豐富（排序集合、排行榜、Pub/Sub） | 單純鍵值 | DynamoDB 項目快取 |
| 持久化／複製 | **支援** | 不支援 | 由服務管理 |
| 多執行緒 | 否 | **是（易水平擴展）** | — |
| 專用對象 | 通用快取、session、排行榜 | 通用物件快取 | **專快取 DynamoDB（微秒級）** |

**考試怎麼選**：「**要持久化／複製／排行榜／進階結構**」→ **Redis**；「**單純、要多執行緒水平擴展的物件快取**」→ **Memcached**；「**加速 DynamoDB 讀取到微秒**」→ **DAX**（別用一般 ElastiCache）。

## 5. CloudFront vs Global Accelerator（全球加速）

| 比較項目 | CloudFront | Global Accelerator |
|---|---|---|
| 做什麼 | **快取內容**到邊緣節點 | 加速**連線路徑**（走 AWS 骨幹） |
| 協定 | HTTP/HTTPS（網站、影片、API） | **任何 TCP/UDP**（遊戲、VoIP、IoT） |
| 固定 IP | 否（給 DNS 名稱） | **是（anycast 靜態 IP）** |
| 內容快取 | **是** | 否 |
| 典型用途 | 靜態／動態網站加速、S3 前面 | 非 HTTP 低延遲、需固定 IP 白名單 |

**考試怎麼選**：「**網站／影片／可快取的內容要全球加速**」→ **CloudFront**；「**非 HTTP 的 TCP/UDP、要固定 anycast IP、不需快取**」→ **Global Accelerator**；「**S3 靜態網站要加速又省流量費**」→ **S3 + CloudFront**。

## 6. Kinesis Data Streams vs Firehose vs SQS（解耦與串流）

| 比較項目 | Kinesis Data Streams | Kinesis Firehose | SQS |
|---|---|---|---|
| 性質 | 即時串流 | 近即時載入 | 訊息佇列 |
| 多消費者讀同一份 | **是** | 否（直接入目的地） | 否（處理後刪除） |
| 可重播 | **是（保留期內）** | 否 | 否 |
| 擴展方式 | 分片 Shard | 全託管自動 | 幾乎無限、自動 |
| 典型用途 | 即時分析、點擊流、多消費者 | 串流自動入 S3/Redshift | 任務佇列、吸收尖峰 |

**考試怎麼選**：「**即時串流、多消費者、要可重播／排序**」→ **Kinesis Data Streams**；「**串流自動入湖到 S3/Redshift、免寫程式**」→ **Firehose**；「**單純任務佇列、一次性消費、吸收尖峰**」→ **SQS**。
