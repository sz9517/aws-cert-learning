# Domain 2 服務比較與考前速查

> 這一頁把 Domain 2（彈性／高可用）裡**最容易混淆**的服務整理成比較表，考前快速掃一遍最有效率。每張表後面都附一句「**考試怎麼選**」的決策提示——看到題幹的關鍵字，就能直接對應到答案。

:::tip[怎麼用這頁]
高可用的題目幾乎都在考「**選型取捨**」：同樣能解決問題的選項擺一起，用「最具成本效益／最高可用／最少營運負擔」這類限定詞逼你選。記住每個服務「只有它能做」的那一格，就是判別點。
:::

## 1. ALB vs NLB vs GWLB（三種負載平衡器）

| 比較項目 | ALB | NLB | GWLB |
|---|---|---|---|
| 作用層 | 第 7 層（HTTP/HTTPS） | 第 4 層（TCP/UDP） | 第 3 層（IP） |
| 路由依據 | 依內容（路徑、主機名、標頭） | 依 IP 與連接埠 | 把流量導到第三方網路設備 |
| 效能／延遲 | 一般 | **極高效能、超低延遲** | 依設備而定 |
| 固定靜態 IP | 否 | **可（靜態／彈性 IP）** | — |
| 典型用途 | Web 應用、微服務、依路徑分流 | 高效能 TCP、固定 IP 白名單 | 串接防火牆／IDS 等資安設備 |

**考試怎麼選**：要依「**網址路徑／主機名**」分流 → **ALB**；要「**極高 TCP 效能**」或「**固定靜態 IP**」→ **NLB**；要在流量路徑中串接「**第三方防火牆／封包檢測設備**」→ **GWLB**。

## 2. SQS vs SNS vs Kinesis Data Streams（訊息／串流）

| 比較項目 | Amazon SQS | Amazon SNS | Kinesis Data Streams |
|---|---|---|---|
| 模式 | 佇列，**拉取（poll）** | 發布／訂閱，**推播（push）** | 即時串流 |
| 對象關係 | 一對一（一則由一個消費者處理） | 一對多（扇出給多個訂閱者） | 一對多，可多消費者重讀 |
| 訊息保留 | 預設 4 天（最長 14 天） | 不保留（送出即走） | 預設 24 小時（最長 365 天），可重播 |
| 典型用途 | 緩衝、解耦、削峰填谷 | 廣播通知、扇出到多個 SQS | 大量即時資料分析、可重放 |

**考試怎麼選**：要「**緩衝、削峰、後端依自己步調處理**」→ **SQS**；要「**一則事件通知多個下游**」→ **SNS**（常搭配多個 SQS 做扇出）；要「**大量即時資料、能重播／多消費者**」→ **Kinesis**。

## 3. SQS 標準佇列 vs FIFO 佇列

| 比較項目 | 標準佇列（Standard） | FIFO 佇列 |
|---|---|---|
| 順序 | 盡力而為，**不保證** | **嚴格先進先出** |
| 傳遞保證 | 至少一次（可能重複） | **剛好一次（exactly-once）**、去重 |
| 吞吐量 | **幾乎無上限** | 較低（高吞吐模式可提升） |
| 典型用途 | 一般解耦、吞吐優先 | 付款、訂單等不可亂序／不可重複 |

**考試怎麼選**：題幹強調「**嚴格順序**」或「**不可重複處理**」→ **FIFO**；只要「**最高吞吐量**」、順序不重要 → **標準佇列**。

## 4. RDS Multi-AZ vs Read Replica vs 跨區複寫

| 比較項目 | Multi-AZ 部署 | Read Replica（唯讀複本） | 跨區複寫 / CRR |
|---|---|---|---|
| 主要目的 | **高可用（自動容錯移轉）** | **讀取擴展** | **災難復原 / 就近讀取** |
| 複寫方式 | 同步 | 非同步 | 非同步（跨 Region） |
| 平時可讀嗎 | **否**（備援待命，不分擔讀取） | **可**（複本可讀） | 可（複本可讀） |
| 主庫故障時 | **自動**切換到備援 | 不會自動接手（可手動升級） | 需手動提升（DR 用） |

**考試怎麼選**：「主庫故障要**自動容錯**、降停機」→ **Multi-AZ**；「**唯讀查詢太多**拖慢主庫」→ **Read Replica**；「**跨 Region 災難復原**」→ 跨區複寫。常見陷阱：Multi-AZ 備援**平時不分擔讀取**。

## 5. 災難復原四策略（RPO/RTO 與成本取捨）

| 策略 | RTO / RPO | 平時成本 | 說明 |
|---|---|---|---|
| Backup & Restore | 最長（數小時以上） | **最低** | 平時只備份，災難時才還原 |
| Pilot Light | 較長 | 低 | 核心（如資料庫）常開，其餘待命、災難時才啟動 |
| Warm Standby | 短（數分鐘） | 中 | 另一 Region 常跑「縮小版」，災難時快速擴大 |
| Multi-Site (Active/Active) | **最短（近乎零）** | **最高** | 多站同時運作，流量即時分擔 |

**考試怎麼選**：越往下走「**RTO/RPO 越小、成本越高**」。看限定詞——「**成本最低**、可容忍數小時」→ Backup & Restore；「**近乎零停機**、不計成本」→ Multi-Site；中間「幾分鐘內恢復又不想雙活全額付費」→ Warm Standby。

## 6. Auto Scaling 擴展策略

| 策略 | 觸發方式 | 適用情境 |
|---|---|---|
| Target Tracking（目標追蹤） | 維持某指標在目標值（如 CPU 50%） | **最常用**、一般自動伸縮首選 |
| Step Scaling（步階） | 依指標超標幅度分級增減 | 需要依嚴重程度做不同幅度調整 |
| Simple Scaling（簡單） | 單一警示觸發固定增減，有冷卻期 | 舊式、較少用 |
| Scheduled Scaling（排程） | 依**時間**預先調整容量 | 流量**規律可預測**（如每天上班時段暴增） |

**考試怎麼選**：「依負載自動維持效能」→ **目標追蹤**；「流量**規律、可預測**、尖峰前先備好」→ **排程擴展**。

## 7. Route 53 路由策略

| 策略 | 依據 | 典型用途 |
|---|---|---|
| Simple（簡單） | 固定回傳 | 單一資源，無特殊需求 |
| Weighted（加權） | 按比例分流 | A/B 測試、金絲雀發布（如 90%/10%） |
| Latency（延遲） | 網路延遲最低 | 多 Region 服務，追求**最佳效能** |
| Failover（故障轉移） | 健康檢查 | 主備（Active/Passive）**自動容錯** |
| Geolocation（地理位置） | 使用者所在國家／地區 | 依地區提供在地內容、法遵限制 |
| Multivalue（多值回應） | 回傳多個健康 IP | 簡易負載分散 + 健康檢查 |

**考試怎麼選**：關鍵字對應——「按比例／金絲雀」→ Weighted；「**延遲最低**」→ Latency；「**健康檢查失敗自動切備援**」→ Failover；「依**使用者國家**」→ Geolocation。注意「延遲最低」≠「地理最近」，別選錯。
